# Cleanzza project guidance

For every Cleanzza development, review, CI, infrastructure, documentation, or release task, read the current `docs/development_rules.md` from the separate documentation repository before making changes. Use the personal `$cleanzza-development` skill when it is installed. From a code repository, the local rules file is normally `../docs/development_rules.md`; from the documentation repository, it is `development_rules.md`.

Treat that file as the canonical development contract. Consult `technical_architecture.md` and `phase_1_product_scope.md` when relevant. Apply the rules for the repository being changed; the Git-flow sections govern the frontend and backend code repositories, while the documentation repository has its own workflow.
