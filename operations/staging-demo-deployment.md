# Synthetic staging deployment

Backend and frontend staging builds come from each repository's `develop` branch. A push to `develop` runs CI and the staging deploy workflow. The deploy workflow archives the exact commit, builds a Docker image on the Cleanzza staging host, updates the Compose image reference, recreates the service, and checks its local health endpoint. The backend script backs up the synthetic PostgreSQL database before migrations. Backend and frontend deployments share a server lock; deploy the backend first when an API contract changes.

The host runs `ENVIRONMENT=demo`, `DEMO_AUTH_ENABLED=true`, `BOOKING_DRAFTS_ENABLED=true`, and `BOOKING_DEMO_ENABLED=true` for the API. The frontend image is built with `NEXT_PUBLIC_DEMO_AUTH_ENABLED=true`, `NEXT_PUBLIC_BOOKING_DRAFTS_ENABLED=true`, and `NEXT_PUBLIC_BOOKING_DEMO_ENABLED=true`. The reverse proxy protects application routes with the “Cleanzza preview - no service will be performed” sign-in prompt and forwards `/demo/customer-session` to the API. These flags must not be used with real customer, worker, identity, payment, or address data. The demo uses synthetic customers, an example pre-tax quote, and a fake payment outcome; it never books a worker or charges a card.

After each rollout, compare the running API and frontend image tags with the short SHAs of their `develop` commits, check `/health/ready` and `/health`, and exercise the Ferrara catalog and synthetic draft flow through the protected preview. A green CI run or a pushed branch alone is not proof of deployment. Preserve the previous Compose file and database backup for rollback. Real launch still needs the [external approval record](phase-1-external-approval-record.md).

Staging worker verification uses `WORKER_VERIFICATION_PREVIEW_ENABLED=true` and a dedicated `WORKER_VERIFICATION_REVIEWER_KEY` from the root-owned `/opt/cleanzza-demo/.env` file. Compose passes both to the API. Reviewer access is at `/admin/verification`. Keep the key out of browser builds, logs, and pull requests. The worker and reviewer flows use [synthetic attachments](../features/worker-document-verification.md).
