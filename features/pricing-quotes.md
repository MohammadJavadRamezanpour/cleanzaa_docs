# Versioned pricing rules and draft quotes (B09)

## Implemented schema slice

Migration `0011_versioned_pricing_rules` creates `pricing_rules`, keyed by `(version, service_code)`. It seeds the approved `milano-hourly-v1` version for the three `milano-v1` catalogue services in `IT-MI-MILANO`. Gross hourly rates are EUR 20.00 Home Cleaning, EUR 25.00 Car Wash, and EUR 20.00 Pet Care. Each row stores currency `EUR`, an exact `NUMERIC(10,2)` hourly gross rate and an exact `NUMERIC(5,4)` platform share rate `0.2000` from ADRs 0004 and 0006. Database checks reject non-EUR currency, unsupported area/service codes, nonpositive rates and invalid share rates. A new price or split requires a new version; existing version rows must remain unchanged after quotes use them. No update/delete API exists.

This first B09 delivery contains rule storage and seed data only. It does not expose a quote endpoint, accept a quote, create an order, calculate tax, or move money. A later B09 slice will calculate decimal draft totals and pin the OpenAPI contract in the frontend. Until Italian tax/invoicing and provider/legal validation are approved, real accepted quote snapshots and booking payments remain disabled. A null or invented zero tax is not a valid accepted snapshot. This gate follows [ADR 0004](../adr/0004-phase-1-pricing-direction.md) and [ADR 0006](../adr/0006-phase-1-payment-direction.md).

There is no HTTP request/response contract, authentication surface, idempotency key, pagination, or file data in this schema slice. The rules are server-owned configuration, not customer or worker input. Application code must load a coherent version and compare catalogue/area/service before using a row. If a rule is missing, future quote calculation must fail closed rather than substitute a hard-coded price. Prices and share rates use decimal arithmetic throughout.

The migration is additive. Its downgrade drops the pricing table and any later versions in it, so do not run it after production quotes reference a version. PostgreSQL integration tests check the seeded values and database constraints. From `back/`, run `.venv/bin/alembic upgrade head`, `.venv/bin/alembic check`, `.venv/bin/pytest -q`, `.venv/bin/ruff check .`, `.venv/bin/ruff format --check .`, `.venv/bin/mypy app scripts`, and `.venv/bin/python -m scripts.export_openapi --check`. The OpenAPI export is unchanged by this database-only slice.
