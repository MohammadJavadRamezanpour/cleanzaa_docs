# Versioned pricing rules and draft quotes (B09)

## Versioned rules and calculator

Migration `0011_versioned_pricing_rules` creates `pricing_rules`, keyed by `(version, service_code)`. It seeds the approved `milano-hourly-v1` version for the three `milano-v1` catalogue services in `IT-MI-MILANO`. Gross hourly rates are EUR 20.00 Home Cleaning, EUR 25.00 Car Wash, and EUR 20.00 Pet Care. Each row stores currency `EUR`, an exact `NUMERIC(10,2)` hourly gross rate and an exact `NUMERIC(5,4)` platform share rate `0.2000` from ADRs 0004 and 0006. Database checks reject non-EUR currency, unsupported area/service codes, nonpositive rates and invalid share rates. A new price or split requires a new version; existing version rows must remain unchanged after quotes use them. No update/delete API exists.

The second B09 delivery adds a server-side `DraftQuoteCalculator`, without an HTTP endpoint. It reads the requested version from PostgreSQL, validates Milano city/CAP, one to three distinct supported services and 1–8 whole hours per service, then calculates each gross line using `Decimal`. It sums the hours for the service window, rounds the total platform share once to EUR cents with half-up rounding, and sets the worker amount to `gross − platform share`. The active rule is `milano-hourly-v1`; a different stored version can be selected internally without changing historical rule rows. A missing/inconsistent rule fails closed. The calculator never substitutes a hard-coded rate.

The internal draft result carries `catalog_version`, `pricing_version`, `currency`, area, service lines, total hours, gross customer total, platform share and worker amount. `tax_amount` and `tax_treatment_version` are explicitly null and `acceptance_ready` is false. The calculator does **not** infer that tax is zero or permit the result to become an accepted order snapshot. Until Italian tax/invoicing and provider/legal validation are approved, real accepted quote snapshots and booking payments remain disabled. This gate follows [ADR 0004](../adr/0004-phase-1-pricing-direction.md) and [ADR 0006](../adr/0006-phase-1-payment-direction.md).

The rules are server-owned configuration, not customer or worker input. Prices and share rates use decimal arithmetic throughout. Invalid inputs raise `QuoteInputInvalid`; missing or incoherent version rows raise `PriceRuleUnavailable`. No transaction writes or asynchronous effects occur in calculation.

## Public draft API

`POST /quotes/drafts` is public so a visitor can preview the service total before creating an account. It accepts JSON with `area_code`, `city`, five-digit `postcode`, and `services` (one to three distinct `{service_code, duration_hours}` entries). The endpoint uses the active server-side price version; clients cannot select or override a rule version. `area_code` must be `IT-MI-MILANO`, city `Milano` case-insensitively, and CAP between `20121` and `20162` inclusive. Each service must be one of the three launch codes and have 1–8 whole hours. Unknown fields are rejected. No street, recipient, schedule, personal information, or payment information is collected by this preview. The future booking flow must validate all service-specific fields and recalculate on any change before acceptance.

A `200` response includes `catalog_version`, `pricing_version`, `currency`, `service_area_code`, `lines` with decimal-string hourly and gross prices, summed `duration_hours`, decimal-string `gross_total`, explicit-offset `quoted_at` and `expires_at` 15 minutes later, `tax_amount: null`, `tax_treatment_version: null`, and `acceptance_ready: false`. It deliberately excludes the internal platform share and worker amount from the customer price preview. Example: 2 hours Home Cleaning plus 1 hour Car Wash returns EUR `65.00` and 3 hours. The display window is informational: this API does not persist or accept a draft. An expired or changed preview must be recalculated. The browser shows the total and expiration in a mobile-width view, has input validation, loading and retryable error states, and no booking action.

Input errors return `422` with standard `VALIDATION_ERROR`; an unavailable price rule or unconfigured calculator returns `503` with `SERVICE_UNAVAILABLE`. Standard request IDs apply. Successful responses use `Cache-Control: no-store`. There is no authentication, ownership check, CSRF requirement, idempotency key, pagination, database write, audit event, or asynchronous effect. The endpoint cannot create an order or trigger payment. Database outage errors still use the server's standard infrastructure error behavior. The backend OpenAPI export and frontend pinned generated types change together in this slice.

The migration is additive. Its downgrade drops the pricing table and any later versions in it, so do not run it after production quotes reference a version. PostgreSQL integration tests check seeded values, constraints, combined-service math, decimal rounding, version independence, invalid area/duration/duplicate service rejection, missing-version failure, and the HTTP API. From `back/`, run `.venv/bin/alembic upgrade head`, `.venv/bin/alembic check`, `.venv/bin/pytest -q`, `.venv/bin/ruff check .`, `.venv/bin/ruff format --check .`, `.venv/bin/mypy app scripts`, and `.venv/bin/python -m scripts.export_openapi --check`. From `front/`, run `npm test`, `npm run lint`, `npm run typecheck`, `npm run contract:check`, `npm run format:check`, and `npm run build`.
