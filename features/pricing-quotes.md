# Versioned pricing rules and draft quotes (B09)

## Implemented schema slice

Migration `0011_versioned_pricing_rules` creates `pricing_rules`, keyed by `(version, service_code)`. It seeds the approved `milano-hourly-v1` version for the three `milano-v1` catalogue services in `IT-MI-MILANO`. Gross hourly rates are EUR 20.00 Home Cleaning, EUR 25.00 Car Wash, and EUR 20.00 Pet Care. Each row stores currency `EUR`, an exact `NUMERIC(10,2)` hourly gross rate and an exact `NUMERIC(5,4)` platform share rate `0.2000` from ADRs 0004 and 0006. Database checks reject non-EUR currency, unsupported area/service codes, nonpositive rates and invalid share rates. A new price or split requires a new version; existing version rows must remain unchanged after quotes use them. No update/delete API exists.

The second B09 delivery adds a server-side `DraftQuoteCalculator`, without an HTTP endpoint. It reads the requested version from PostgreSQL, validates Milano city/CAP, one to three distinct supported services and 1–8 whole hours per service, then calculates each gross line using `Decimal`. It sums the hours for the service window, rounds the total platform share once to EUR cents with half-up rounding, and sets the worker amount to `gross − platform share`. The active rule is `milano-hourly-v1`; a different stored version can be selected internally without changing historical rule rows. A missing/inconsistent rule fails closed. The calculator never substitutes a hard-coded rate.

The internal draft result carries `catalog_version`, `pricing_version`, `currency`, area, service lines, total hours, gross customer total, platform share and worker amount. `tax_amount` and `tax_treatment_version` are explicitly null and `acceptance_ready` is false. The calculator does **not** infer that tax is zero or permit the result to become an accepted order snapshot. No quote endpoint, accepted quote, order, or payment exists yet. A later B09 PR will expose the draft result over HTTP and pin the OpenAPI contract in the frontend. Until Italian tax/invoicing and provider/legal validation are approved, real accepted quote snapshots and booking payments remain disabled. This gate follows [ADR 0004](../adr/0004-phase-1-pricing-direction.md) and [ADR 0006](../adr/0006-phase-1-payment-direction.md).

There is no HTTP request/response contract, authentication surface, idempotency key, pagination, or file data in these first two slices. The rules are server-owned configuration, not customer or worker input. Prices and share rates use decimal arithmetic throughout. Invalid inputs raise `QuoteInputInvalid`; missing or incoherent version rows raise `PriceRuleUnavailable`. No transaction writes or asynchronous effects occur in calculation.

The migration is additive. Its downgrade drops the pricing table and any later versions in it, so do not run it after production quotes reference a version. PostgreSQL integration tests check seeded values, constraints, combined-service math, decimal rounding, version independence, invalid area/duration/duplicate service rejection, and missing-version failure. From `back/`, run `.venv/bin/alembic upgrade head`, `.venv/bin/alembic check`, `.venv/bin/pytest -q`, `.venv/bin/ruff check .`, `.venv/bin/ruff format --check .`, `.venv/bin/mypy app scripts`, and `.venv/bin/python -m scripts.export_openapi --check`. The OpenAPI export is unchanged by these internal slices.
