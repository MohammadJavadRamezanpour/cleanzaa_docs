# Customer booking form (B10)

The mobile `/book` page loads `GET /catalog/launch` and offers Home Cleaning in the Ferrara pilot area. It collects service date/start time in `Europe/Rome`, Ferrara street/house/CAP, recipient type and optional other-recipient contact, 1–8 whole hours, room selection/count, beginner/professional preference, and equipment/supplies choice. The city and area come from the server catalog; the backend checks `IT-FE-FERRARA`, `Ferrara`, and `44121`–`44124` again. Car Wash, Pet Care, Milano, and other cities are not active choices. The CAP check does not confirm an exact address.

The form validates shared and service-specific fields with inline errors and keyboard labels. It requests `POST /quotes/drafts` after a 300 ms edit pause, sending only area, city, CAP, service code, and hours. The server supplies the active `ferrara-demo-v1` example amount. The frontend ignores superseded responses, clears stale previews when price inputs change, and expires previews after 15 minutes. It labels the amount as a **demo example base**, with tax and final customer price unapproved. It does not infer eligibility or availability from client validation.

In an explicitly configured local demo, a signed-in synthetic customer may save a draft and simulate submission at the same example amount. Saving sends the full details with CSRF and an `Idempotency-Key`; the backend owns validation, quote snapshot, schedule conversion, and retry behavior. The simulated payment uses a fake provider and creates no real booking, charge, or dispatch. In other environments the booking gate remains visible and submission is unavailable. The [order-history feature](order-history-foundation.md) covers the saved draft and simulation contracts.

The current frontend pins the backend OpenAPI export, including the Ferrara catalog and historical draft-read shape. The change removes inactive services from the active client flow. Run `npm test`, `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm run contract:check`, and `npm run build`. Review `/book` at phone and desktop widths. No real tax rate, fiscal document, payment method, or live provider activation is implemented.
